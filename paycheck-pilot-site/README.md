# The Paycheck Pilot — website

Static website for The Paycheck Pilot (thepaycheckpilot.com): money guides for hourly and biweekly US workers. Monetized with affiliate links (wired in later — see below).

## Generator choice: Hugo

Hugo was chosen over Eleventy for one reason: **it is a single self-contained binary with zero runtime dependencies.** No Node, no `npm install`, no `node_modules`, no version drift between local builds and production. The entire site builds in under a second, and Cloudflare Pages supports Hugo natively — you set a `HUGO_VERSION` environment variable and it just works. For a site whose whole point is "nothing to maintain," the build tool shouldn't be the thing that breaks. Content is plain Markdown files; the layout is hand-written semantic HTML with one CSS file and no JavaScript, so there's almost nothing that *can* rot.

## Build locally

You need the Hugo extended binary (one file, no install):

```bash
# Download once (Linux x64 example; check github.com/gohugoio/hugo for your OS)
curl -sL -o /tmp/hugo.tar.gz "https://github.com/gohugoio/hugo/releases/download/v0.152.2/hugo_extended_0.152.2_linux-amd64.tar.gz"
tar -xzf /tmp/hugo.tar.gz -C /tmp hugo

# Build the site (output goes to ./public/)
/tmp/hugo --source /path/to/site

# Or preview with live reload while writing:
# /tmp/hugo server --source /path/to/site
```

To lock the version for everyone, keep a copy of the binary at `~/workspace/bin/hugo` and reference that path instead of `/tmp/hugo`.

## Deploy to Cloudflare Pages (git push flow)

1. Push this `site/` directory to a GitHub repo.
2. In Cloudflare dashboard: **Workers & Pages → Create → Pages → Connect to Git** → select the repo.
3. Build settings:
   - **Build command:** `hugo`
   - **Build output directory:** `public`
   - **Environment variable:** `HUGO_VERSION = 0.152.2`
   - (Root directory: `site` if the repo contains more than the site.)
4. Add the custom domain `thepaycheckpilot.com` under **Custom domains** once it's purchased — Cloudflare provisions SSL automatically.
5. Every `git push` to the main branch rebuilds and redeploys. No servers, no dashboards to babysit.

## Where affiliate links get wired in

Affiliate links are **not** hardcoded in articles. They're centralized in one file:

- **`data/affiliates.yaml`** — maps keys (`ynab`, `rocket-money`, `monarch-money`, `sofi`, `discover`, `amazon`) to URLs. All values are currently `"#"` (placeholder).
- **Shortcode** `layouts/shortcodes/aff.html` — used in content as `{{< aff "ynab" "YNAB" >}}`. Renders `rel="sponsored nofollow noopener"` automatically.

**When a program approves the site:** edit `data/affiliates.yaml`, replace the `"#"` with the real tracking URL, push. Every article using that key updates site-wide. Nothing else to touch.

## FTC compliance (already built in)

Affiliate networks require disclosure *before* they approve a site. This is handled three ways:

1. **Site-wide banner** (`layouts/partials/disclosure-banner.html`) — shown at the top of every article.
2. **Per-article disclosure** — full disclosure statement at the bottom of every article template (`layouts/articles/single.html`).
3. **Standalone pages** — `/disclosure/` (affiliate disclosure) and `/privacy/` (privacy policy), linked from the footer of every page.

## Content

- `content/articles/` — Markdown articles. Front matter: `title`, `description`, `date`.
- To publish: add a `.md` file, push. The home page "Latest articles" and `/articles/` index update automatically.
- XML sitemap is generated by Hugo on every build; `robots.txt` lives in `static/`.

## Structure

```
site/
├── hugo.toml              # config (baseURL, title, params)
├── content/               # Markdown: home, articles, about, contact, disclosure, privacy
├── data/affiliates.yaml   # THE affiliate link registry (edit this when approved)
├── layouts/               # templates + aff shortcode + partials
├── static/                # robots.txt, css/style.css (copied verbatim)
└── README.md              # this file
```
